## 目的

提交不符合要求的注册输入（邮箱格式错误、昵称为空、口令短于 12 字符）时，请求被拒绝，不创建账号、不建立会话。

## 前置条件

- 非生产环境，仅使用合成数据。
- 具备可发出 JSON 注册请求的受控能力；页面表单的原生校验会阻止不合法输入提交，因此本场景需直接调用接口。

## 步骤

1. 向 `POST /api/auth/register` 发送邮箱不含 `@` 的请求。
2. 向同一接口发送昵称为空的请求。
3. 向同一接口发送口令长度不足 12 字符的请求。
4. 每次请求后读取 `GET /api/auth/status`，并尝试用对应邮箱与口令登录。

## 期望

- 三次请求均被拒绝（非 2xx），不设置会话 Cookie。
- 每次拒绝后 `GET /api/auth/status` 均为未登录状态。
- 这些邮箱与口令组合无法登录成功，即未创建可用账号。

## 需要记录

- 每次请求的响应状态与响应体错误标识（作为观察记录，不复述口令值）。
- 拒绝后的会话状态与登录尝试结果。
- 确认无账号残留（可用受控清理与存储观察核验）。
